## 🔍 Part 1: Forensic Root Cause Analysis

### 1. The Subscriptions Policy Trap: Breakdown vs. Billed Prominence
* **The Rule**: Under Google Play's Subscriptions and Billing Transparency Policies, developers must not mislead users by making monthly breakdown costs (e.g. `"$3.33/mo"`) more visually prominent than the actual commitment or renewal charge (`"$39.99/year"`).
* **The Flaw in v1.5.5**: On the Annual Explorer Pass tile, `"$3.33 / mo"` was rendered in a 14pt heavy bold font, while the actual billed amount `"$39.99/yr • Save 66%"` was displayed in small 8.5pt subtext below it.
* **Why it Passed Earlier**: Automated pre-launch crawlers only test for crashes and basic navigation. When v1.5.5 crashed during human interaction, the app was escalated to a human Google reviewer in Mountain View who took a manual screenshot and flagged the breakdown pricing violation.

### 2. The Native Crash Root Cause (`"PoquitoTalk keeps stopping"`)
Inspecting the crash dialog (`IN_APP_EXPERIENCE-5009.png`) revealed a fatal uncaught exception during initialization:
* **The Web Stripe Key Leak**: In `src/services/revenuecat.ts`, the configure step was passing a Web Stripe public key (`strp_oRCQHGzTOCydzvQECdMeNnbVXTI`) into `Purchases.configure({ apiKey })`. Because Android expects a Google Play Store public key (`goog_...`) or offline mode, the native `purchases-hybrid-common` bridge threw a fatal Java/JNI exception upon cold launch.
* **The Race Condition in Layers**: `src/services/layersService.ts` called `Purchases.getCustomerInfo()` and registered `Purchases.addCustomerInfoUpdateListener` unconditionally on startup. If RevenueCat hadn't completed native setup, Kotlin threw `kotlin.UninitializedPropertyAccessException: lateinit property has not been initialized`.
* **Missing Android 13+ Notification Permission**: `AndroidManifest.xml` lacked `<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>`, triggering unhandled permission rejections when scheduling the new WhatsApp return heads-up banner.

### 3. The Mystery of the Missing Mascot
Why did Poquito vanish from the Google Play review screenshot?
* `SoftOnboardingPaywall.tsx` was loading an animated WebP file: `poquito_talk_58_73_160.webp`.
* In `android/gradle.properties`, the flag `expo.webp.animated=false` was configured to save memory.
* As a result, Facebook Fresco (the native image rendering engine on Android) silently ignored animated WebP frames, rendering a 100% transparent zero-byte frame that left an awkward empty white gap right above the headline.

## 🏆 Part 5: How Claude Opus 5.5 Saved the Submission & The "Funnel Vision" Breakthrough (v1.5.8 Shipped!)

Just when we thought v1.5.6 was ready to fly, **Claude Opus 5.5** conducted a deep, forensic second-pass code audit that literally saved our entire submission from an immediate Google Play policy rejection and potential billing disaster.

### 🦅 The 4 Traps Claude Opus 5.5 Caught Before Review:

1. **The Fallback Pricing Trap (Disaster Averted)**:
   * *The Bug*: In `purchaseProPackage(tier)`, if a user or reviewer clicked "50 Credits Pack" on mobile, the tier switch didn't have an explicit match. It fell back to `availablePackages[0]`, which is the **Annual Pass ($39.99/year)**!
   * *The Consequence*: A user trying to buy $4.99 of one-time credits could have been enrolled in a $39.99/year auto-renewing subscription. Google Play reviewers would have flagged this as an egregious deceptive billing practice.
   * *The Fix*: Rewrote `purchaseProPackage(tier)` with strict tier matching. It never defaults to the first package if a specific tier was requested. If unmapped, it gracefully aborts.

2. **The 7-Day Travel Pass Wording Mismatch**:
   * *The Issue*: The paywall copy stated: *"One-time charge of $4.99. Does not auto-renew"*, but the code looked for a weekly subscription package. 
   * *Google Play Policy*: Subscription wording must strictly match the store's billing behavior. Under our Google Play Console configuration, `poquitotalk_travel_pass` is set up as an official **`prepaidBasePlanType`** (`P1W`, non-renewing with time extension).
   * *The Fix*: We updated the paywall across both `SoftOnboardingPaywall.tsx` and `PaywallModal.tsx` to exact Google Play prepaid subscription terminology:
     - Subtitle: **`Prepaid • Non-renewing`**
     - Disclosure: **`Prepaid 7-day access for $4.99. Does not auto-renew. Top up anytime.`**

3. **The Dead "Silent Spinner" (Reviewer Trap)**:
   * *The Issue*: When a purchase returned `false` (e.g. during backend sync or sandbox latency), the loading spinner simply vanished with zero user feedback. To a human Google reviewer, the app appeared completely frozen.
   * *The Fix*: `purchaseProPackage` now returns `{ success, userCancelled, errorMessage }`. If a store error occurs, the app presents an informative `Alert.alert('Store Notice', ...)` explaining the state rather than hanging in silence.

4. **Git Security & Secret Untracking**:
   * *The Issue*: `.projects/vault/vault.json` was tracked in git history despite being in `.gitignore`.
   * *The Fix*: Executed `git rm --cached .projects/vault/vault.json` to purge it from git index tracking.
